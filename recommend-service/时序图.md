# 一、首页推荐整体时序图（核心主链路）

```
用户
 │
 │  GET /api/recommend/home
 ▼
RecommendController
 │
 │  构建 RecommendRequest
 ▼
RecommendService.recommend()
 │
 │──(1) 查缓存 rec:result:home:{user}
 │        ├──命中 → 直接返回
 │        └──未命中 ↓
 │
 │──(2) 多策略召回
 │        ├──HotRecallStrategy
 │        │     └──Redis ZSET rec:hot:home
 │        │
 │        ├──TagRecallStrategy
 │        │     └──UserProfileService.getProfile()
 │        │           ├──Redis rec:profile:{user}
 │        │           └──DB user_profile_snapshot（兜底）
 │        │     └──QuoteMapper.selectByTags()
 │        │
 │        ├──TopicRecallStrategy
 │        │     └──同上 → selectByTopicIds()
 │        │
 │        ├──AuthorRecallStrategy
 │        │     └──selectByAuthors()
 │        │
 │        ├──SimilarRecallStrategy
 │        │     └──Redis rec:similar:{contentId}
 │        │
 │        └──ColdStartRecallStrategy（兜底）
 │              └──selectRecentPublished()
 │
 │──(3) 合并候选集（CandidateItem）
 │
 ▼
RankService
 │
 │──(4) deduplicate()
 │        └──合并重复 contentId
 │
 │──(5) filterSeen()
 │        └──Redis rec:seen:{user}
 │
 │──(6) 批量加载内容特征
 │        └──ContentFeatureService.getBatchByIds()
 │              ├──Redis rec:feature:{id}
 │              ├──DB content_feature_snapshot
 │              └──DB quote（兜底）
 │
 │──(7) 排序 rank()
 │        ├──UserProfileService.getProfile()
 │        ├──计算 interestScore
 │        ├──融合：
 │        │    interest + hot + quality + freshness + baseScore
 │        └──排序
 │
 ▼
RecommendService
 │
 │──(8) 写缓存 rec:result:home:{user}
 │
 │──(9) 分页
 ▼
RecommendController
 │
 ▼
返回推荐列表
```

# 二、详情页相关推荐时序图（相似推荐核心）

```
用户
 │
 │ GET /api/recommend/related/{contentId}
 ▼
RecommendController
 │
 ▼
RecommendService.related()
 │
 │（内部还是调用 recommend()）
 ▼
RecommendService.recommend()
 │
 │──(1) SimilarRecallStrategy
 │        ├──seed = 当前 contentId
 │        └──Redis rec:similar:{contentId}
 │
 │──(2) + 其他策略补充（热门/标签等）
 │
 ▼
RankService
 │
 │──deduplicate
 │──filterSeen
 │──加载内容特征
 │──排序（更偏向相似度）
 │
 ▼
返回相关推荐
```

# 三、用户行为上报时序图（驱动推荐核心）

```
用户操作（浏览/点赞/收藏/评论）
 │
 │ POST /api/behavior/xxx
 ▼
BehaviorController
 │
 ▼
BehaviorService.record()
 │
 │──(1) 写 MySQL
 │        user_behavior_event
 │
 │──(2) 如果是 view
 │        └──Redis rec:seen:{user}（Set）
 │
 │──(3) 更新用户画像
 │        ▼
 │   UserProfileService.updateProfile()
 │        ├──读取画像
 │        │    Redis → DB → new
 │        │
 │        ├──计算权重
 │        │    actionWeight * timeDecay
 │        │
 │        ├──读取内容特征
 │        │    ContentFeatureService.getById()
 │        │
 │        ├──更新：
 │        │    tagWeights
 │        │    topicWeights
 │        │    authorWeights
 │        │    dynastyWeights
 │        │    categoryWeights
 │        │
 │        ├──更新最近浏览列表
 │        │
 │        ├──写 Redis rec:profile:{user}
 │        │
 │        └──写 DB user_profile_snapshot
 │
 │──(4) 更新活跃用户
 │        Redis rec:active:users (ZSET)
 │
 ▼
返回 OK
```

# 四、热榜计算任务时序图

```
定时任务（每小时）
 │
 ▼
HotRankJob
 │
 │──(1) 查询 MySQL
 │        UserBehaviorMapper.selectHotStats()
 │
 │──(2) 计算热度分
 │        view*1 + like*3 + favorite*5 + comment*6
 │        * 时间衰减
 │
 │──(3) 清空 Redis
 │        rec:hot:home
 │
 │──(4) 写入 ZSET
 │        score 排序
 │
 ▼
完成
```

# 五、内容相似计算任务时序图

```
定时任务（每2小时）
 │
 ▼
ItemSimilarityJob
 │
 │──(1) 查询最近内容
 │        QuoteMapper.selectRecentPublished(300)
 │
 │──(2) 两两计算相似度
 │        ├──作者相同
 │        ├──朝代相同
 │        ├──分类相同
 │        ├──标签交集
 │        └──话题交集
 │
 │──(3) 每个内容取 Top20
 │
 │──(4) 写 Redis
 │        rec:similar:{contentId}
 │
 ▼
完成
```

# 九、你可以这样理解这套系统

一句话总结：

👉 **这是一个“多路召回 + 用户画像打分 + 规则排序”的推荐系统**

它的本质是：

- 召回：找候选
- 画像：理解用户
- 排序：决定顺序
- 行为：不断反馈优化
